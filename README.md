# 冰盞紅 — 官方線上訂購網站

手作酸梅湯品牌「冰盞紅」的線上訂購網站。純 HTML / CSS / JavaScript，**沒有框架、不需編譯**，
用瀏覽器直接打開 `index.html` 就能看到成果，丟到任何靜態主機就能上線。

---

## 設計系統（CI）

色彩全部取自實際瓶身標籤：**朱紅盞 × 墨綠環 × 宣紙米白**。
定義在 `assets/css/site.css` 最上方的 `:root`，改色只要改那一段。

| 變數 | 值 | 角色 |
|---|---|---|
| `--red` | `#C0281B` | 朱紅。價格、主按鈕、字標的「紅」 |
| `--green` | `#20604F` | 墨綠。**結構色**：線條、頁首頁尾、標籤、次要按鈕 |
| `--gold` | `#B8891C` | 桂花金。點綴，用得極少 |
| `--paper` | `#F7F1E3` | 宣紙米白。頁面底色 |
| `--surface` | `#FFFCF6` | 卡片 |
| `--ink` | `#241F1B` | 內文。偏暖的黑 |

**用色原則：墨綠當結構色大量使用，朱紅只留給「要按的東西與價格」。**
朱紅配米白的對比度約 5.4:1，墨綠約 7.2:1——主客群含中高齡，長文用墨綠比較好讀。

字體：標題 Noto Serif TC（只載入一個字重）、內文用系統字（零下載）、數字與訂單編號 IBM Plex Mono。
品牌字標「冰盞紅」是毛筆手寫，以 `assets/img/wordmark.png`（從官方橫式組合去白底裁出）在頁首使用。

`assets/img/logo.svg` 與 `favicon.svg` 是依業主提供的官方標誌（`logo-official.jpg`）重繪的向量版，
網頁與 favicon 使用；**印刷請以官方原始檔為準**。

## 改完任何東西之後：跑 `build.py`

```bash
python build.py
```

它會把 `partials/` 的頁首、頁尾、底部列同步進八個頁面（**改頁尾只要改一次**），
幫 CSS／JS 連結加上內容雜湊版本號（改檔後快取自動失效，**不用再手動改 `?v=`**），
有 `.webp` 的圖片自動用 `<picture>` 包起來，並依 `config.js` 的 `site.url` 產生 `sitemap.xml`。

輸出仍是純 HTML，直接開檔就能看。共用片段的位置在各頁的
`<!-- @include:header sub="…" -->` … `<!-- @end:header -->` 之間，**不要手動改那裡面的內容**，改 `partials/` 再組建。

## 上線前：跑 `check.py`

```bash
python check.py --strict
```

列出所有還不能上線的原因：連結壞掉、圖片沒到、還有 `[待確認]`、草稿還沒經業主確認、`config.js` 的 API 或網址沒填。
全部綠燈才上線。

## 最重要的一件事：`assets/js/config.js`

**價格、電話、LINE、活動文案、銀行帳號，全部集中在這一個檔案。**
改一次，首頁、訂購頁、完成頁、說明頁會同時更新，不會發生「首頁改了價格、訂購頁忘了改」的狀況。

例如要調整售價，只需要改這裡：

```js
plans: [
  { id:'box1', boxes:1, bottles:12, price:1490, ... },
  { id:'box2', boxes:2, bottles:24, price:2880, ... }
]
```

### 中秋檔期結束後怎麼辦

把 `config.js` 裡這一行改成 `false`：

```js
campaign: { enabled: false, ... }
```

全站文案會自動從「中秋分享箱／今年中秋，冰箱裡也準備一箱。」
切換成常態版「冷藏分享箱／冰箱裡常備一箱，吃飯配一杯。」，**不用重做網站**。

### 其他開關

| 設定 | 用途 |
|---|---|
| `site.url` | 正式網址，給 sitemap 與分享連結用 |
| `analytics.ga4` | GA4 評估 ID。留空完全不載入；填了隱私權頁會自動換成有追蹤的版本 |
| `campaign.deadline` / `deliveryWindow` | 檔期最後下單日與送達區間，顯示在首頁 |
| `remember.enabled` | 訂購頁「記住收件資料」（只存客人自己的裝置） |
| `lineQr` | 官方 LINE 加好友 QR Code 圖片，桌機客人在完成頁掃描用 |

### 缺貨或來不及做的時候

手工小批次一定會遇到。改 `config.js` 的 `stock.status` 一個字即可，全站自動反應：

| 值 | 效果 |
|---|---|
| `'open'` | 正常接單（預設） |
| `'preorder'` | 頁首下方出現金色提示條說明開放預購，訂購功能照常 |
| `'closed'` | 出現紅色提示條，所有「立即訂購」改成 LINE 詢問，訂購表單停用 |

```js
stock: { status: 'preorder', ... }
```

### ⚠ 改完 `config.js` 記得跑 `python build.py`

瀏覽器會快取 `config.js`。`build.py` 會依檔案內容產生新的版本號，讓來過的客人也拿到新價格。
不跑組建，改了價格老客人可能還看到舊的。

## 第 1 步：把圖片放進去

規格見 [`IMAGE-BRIEF.md`](IMAGE-BRIEF.md)——每張圖的檔名、尺寸、內容，
以及「哪些能生成、哪些必須實拍」的規則（有瓶子入鏡的畫面一律用實拍，不要生成假瓶子）。

在放入圖片之前，網頁會顯示灰色的「【待製圖】」提示框，不會破圖。
部分位置設有 `data-fallback`：正式圖還沒到時先用同組已完成的圖暫代（例如首頁主視覺暫用 `drink-1.jpg`）。

目前狀態：食材八張與喝法四張已由 Codex 產出（PR #1），並已轉出 WebP 版本。
主視覺、瓶身、製程、餐桌、冰箱、故事頁主圖等 7 張需實拍，仍待業主提供。

## 第 2 步：開通訂單系統（訂單寫入 Google 試算表）

**在完成這一步之前，訂購表單不會假裝訂單已送出。** 它會清楚告訴客人
「線上訂單系統尚未開通」，並把訂單內容整理好讓客人用 LINE 傳給你。

### 安裝流程

1. 到 [Google 試算表](https://sheets.google.com) 建立一份新試算表，名稱例如「冰盞紅訂單」。
2. 上方選單 **擴充功能 → Apps Script**。
3. 把 `google-apps-script/Code.gs` 的**全部內容**貼上，覆蓋原本的 `myFunction`。
4. 如果想收到新訂單通知信，把最上面的 `NOTIFY_EMAIL` 填入你的 Gmail。
5. 上方函式選單選擇 **`setup`**，按 **執行**。第一次會要求授權，請允許。
   完成後試算表會出現「訂單」「付款回報」「團購詢價」三個工作表，並附帶狀態下拉選單。
6. 右上角 **部署 → 新增部署作業**：
   - 類型選 **網頁應用程式**
   - 「執行身分」選 **我**
   - 「具有存取權的使用者」選 **任何人**
   - 按下部署，複製產生的**網頁應用程式網址**（結尾是 `/exec`）
7. 打開 `assets/js/config.js`，把網址貼進去：

```js
api: {
  url: 'https://script.google.com/macros/s/AKfycb....../exec'
}
```

完成。之後每一筆訂單都會即時寫進試算表，訂單編號格式為 `BZH-20260910-001`。

> 修改 `Code.gs` 後，必須再執行一次「部署 → 管理部署作業 → 編輯 → 版本選新版本」，
> 網址才會更新到最新程式。

### 試算表會記錄哪些欄位

部署後試算表會出現三個工作表：

**「訂單」**：訂單編號、訂購日期、訂購人、訂購人電話、收件人、收件人電話、**配送縣市**、配送地址、
Email、方案、箱數、瓶數、商品金額、處理費、訂單金額、付款方式、**付款狀態**、**訂單狀態**、
備註、**送禮**、**賀卡留言**、檔期、建立時間。

**「付款回報」**：客人自己填的轉帳後 5 碼與付款日期。有填訂單編號時，會自動把該筆訂單的付款狀態改成「待核對」。

**「團購詢價」**：`wholesale.html` 送出的企業／團購需求。

「付款狀態」與「訂單狀態」欄位已設好下拉選單，出貨進度直接在試算表上改即可：

- 付款狀態：待付款 / 待核對 / 已付款 / 貨到付款 / 未完成
- 訂單狀態：待確認 / 備貨中 / 已出貨 / 已完成 / 已取消

客人在 `status.html` 查詢訂單時，看到的就是這兩欄的內容。

## 上線前必須補齊的資料（目前標示為 `[待確認]`）

以下欄位在 `config.js` 中，網頁上會以灰字顯示 `[待確認]`，**上線前請務必替換**：

| 位置 | 項目 | 說明 |
|---|---|---|
| `bank.*` | 銀行、代號、分行、帳號、戶名 | ATM 轉帳用。未填時完成頁會請客人用 LINE 索取帳號 |
| `assets/img/linepay-qr.png` | LINE Pay 收款 QR Code | 未放入前不會顯示假的 QR Code |
| `contact.hours` | 客服服務時間 | 例：每日 10:00–20:00 |
| `shipping.leadTime` | 出貨時間 | 例：訂單確認後 2–3 個工作天出貨 |
| `shipping.areaNote` | 配送地區限制 | 例：本島配送，外島與部分山區請先詢問 |
| `legal.*` | 營業人名稱、統一編號、食品業者登錄字號、地址 | 頁尾與隱私權頁 |
| `info.html` | 退換貨處理方式、個資保存期間、七日猶豫期條文用語 | 建議請熟悉食品／電商法規者確認後填寫 |

## 網站不會做的事（刻意的設計）

1. **不會假裝有金流串接。** 沒有信用卡欄位、沒有假的付款成功畫面。
   ATM 與 LINE Pay 都明確標示為「人工核對款項」。
2. **不會假裝訂單已送出。** 後端未設定或連線失敗時，完成頁會顯示
   「訂單尚未送出」，並提供訂單內容讓客人用 LINE 傳送。
3. **不會產生假資料。** 沒有捏造的銀行帳號、QR Code、公司統編、食品登錄字號。
4. **不做療效宣稱。** 全站文案只使用一般食品的生活性描述。

## 給客人的訂購流程

```
首頁 → 看方案（1 箱 1,490 / 2 箱 2,880）
     → 訂購頁：選方案 → 選付款方式 → 填收件資料
     → 底部固定列即時顯示應付金額
     → 送出
     → 完成頁：顯示訂單編號 + 依付款方式給下一步
        ├ ATM      → 顯示匯款帳戶 → 「我已完成轉帳，前往回報」
        ├ LINE Pay → 顯示 QR Code → 「我已完成付款，前往回報」
        └ 貨到付款 → 說明送達時應付金額
     → 付款回報頁：填訂單編號 + 帳號後 5 碼 → 寫入試算表
```

## 給店家的日常作業

1. 早上打開試算表「訂單」工作表，看有沒有新的一列。
2. 對照「付款回報」工作表的後 5 碼，核對銀行入帳。
3. 核對完成 → 把該筆訂單的「付款狀態」改成 **已付款**，「訂單狀態」改成 **備貨中**。
4. 出貨後改成 **已出貨**。客人在網站上查詢時就會看到最新狀態。
